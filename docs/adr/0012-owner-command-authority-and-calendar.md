# ADR 0012 — точная команда владельца как полномочие на обратимое действие

**Статус решения:** ACCEPTED
**Состояние реализации:** PARTIAL
**Дата:** 24 июля 2026
**Заменяет:** ADR 0008 в части требования отдельной кнопки для любого внешнего изменения

## Контекст

Повторное подтверждение каждой команды делало личного Telegram-оркестратора
медленным и непригодным для календаря, документов и обычных owner-only операций.
При этом полное снятие подтверждений создало бы риск удаления, публикации, денежных
операций и отправки данных не тому адресату.

## Решение

Аутентифицированная точная текстовая команда владельца является полномочием на
указанное обратимое действие в разрешённом scope. Локально распознанная голосовая
команда имеет тот же статус и не требует второй кнопки.

Без дополнительного L4 разрешены:

- чтение, анализ и public-web research;
- создание нового локального результата в owner workspace;
- идемпотентное редактирование с snapshot, diff, атомарной записью и rollback;
- получение владельцем файла в том же связанном Telegram-чате;
- просмотр, создание и изменение событий Google Calendar;
- создание и изменение Google Tasks по точной команде;
- ответы бота владельцу в исходной control-plane сессии.

Всегда требуют отдельного action-bound L4:

- удаление локального или внешнего объекта;
- деньги, покупки и платежи;
- публикация и отправка клиенту или третьей стороне;
- изменение прав, credentials, OAuth scopes и security settings;
- push, remote, deployment и production migration;
- необратимое либо неоднозначное массовое действие.

L1/L2/L3 проверяют реализацию, новый тип процесса и результат повышенного риска.
Они не создают четыре пользовательских клика для каждой повторяемой операции.

## Календарный контур

LLM используется только как закрытый intent parser без tools, web и файлов. Он
возвращает строгий `CalendarAction`; детерминированный adapter повторно валидирует
тип, время, target и idempotency key.

`LIST`, `CREATE` и `UPDATE` исполняются сразу. `DELETE` сначала разрешает ровно
одно событие, затем сохраняет связанный с tenant/user/chat/event capability и
выполняется только после отдельной одноразовой кнопки владельца. Неоднозначный
target отклоняется.

Создание использует детерминированный Google event ID. Повтор того же payload
возвращает существующее событие; тот же idempotency key с другим payload
fail-closed как конфликт.

## Голосовой контур

Русский язык фиксируется явно; используются beam search, VAD, отключённый
cross-segment context и словарь терминов Nobus/PROстранство/маркетплейсов.
Whisper остаётся локальным и прогревается до начала polling. Удаление,
распознанное голосом, всё равно переходит к отдельному L4.

## Последствия

Положительные:

- обычные owner-команды выполняются без лишнего диалога;
- одна политика действует одинаково для текста и голоса;
- удаление остаётся exact-action bound;
- replay и конфликт idempotency проверяются на server boundary.

Остаточные ограничения:

- локальная модель `base/int8` улучшена настройками, но не равна по точности
  более крупной модели;
- Google Tasks, Drive и Business Notes реализуются отдельными следующими блоками;
- публикация новой live-версии возможна только после полного L2/L3 и release L4.
