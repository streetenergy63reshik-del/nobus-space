## Источники истины и обновление

1. Прямое решение владельца и применимые правила проекта определяют полномочия и критерии.
2. Принятые ADR и контракты задают границы продукта.
3. Точная Git revision с привязанными проверками подтверждает реализацию; защищённая GitHub main и релизные теги — канон опубликованной истории.
4. CURRENT кратко отражает принятые версии и время наблюдения. Исторические материалы и Nobus Memory дают контекст, но не заменяют Git.

CURRENT означает подтверждённый факт, TARGET/PROPOSED — ещё не реализованный план, FROZEN / NOT CURRENT — сохранённую неактивную архитектуру. Позднейшая дата документа не делает старое доказательство новой проверкой.

Обновляйте существующий документ по его роли. Не создавайте параллельные dated/final/v2 статусы; промежуточная история остаётся в Git и соответствующем Gate. Не переписывайте запечатанные доказательства и не переносите в Git secrets, runtime, логи, raw payload, аудио или закрытые архивы. Ненужный файл удаляется после проверки ссылок, потребителей и восстанавливаемости.

Документные изменения проверяются ссылками, согласованностью статусов, `tests/test_documentation.py` и `git diff --check`. Изменение навигации не запускает заново принятие продукта. Обычный WIP получает целевые проверки; независимые L1/L2/L3 относятся к цельному кандидату там, где это требуется контрактом. Документы 06/07 сохраняют отдельные правила разрешений работающего продукта.
