# ADR-0004. Сначала измерять расход, затем вводить бюджеты

**Статус решения:** ACCEPTED

**Дата:** 2026-07-20

## Контекст

До реальной эксплуатации неизвестны нормальные расходы по ролям, моделям и типам задач. Жёсткие бюджеты без данных будут случайно прерывать полезные задачи или ничего не защищать.

## Решение

MVP записывает фактический usage/cost по tenant, task, attempt, provider, model, contract/policy version и времени. Автоматическая оптимизация и сложная система бюджетов откладываются до репрезентативной выборки.

При этом сохраняются базовые предохранители: timeout, ограничение размера ввода/вывода, конечное число retries и возможность административно отключить provider. Неизвестная стоимость не разрешает бесконечный запуск.

## Последствия

Положительные:

- бюджеты позже основаны на распределении реальных расходов;
- можно сравнивать workers и выявлять аномалии;
- меньше ранней конфигурационной сложности.

Отрицательные:

- первая эксплуатация требует ручного наблюдения cost dashboard;
- без полноты usage records решение о бюджете невозможно.

## Критерий перехода к бюджетам

После согласованного объёма успешных задач и проверки полноты данных определяется baseline по типу задачи. Отдельное решение задаёт warn/stop thresholds, поведение при исчерпании и исключения для критических задач.
