# 5 октября 2026: связь с обновлённым Codex Desktop

**17:15 МСК, исправление выпущено.** LIVE использует
`17651308ce8a9d6a1f27199955b13f42de019978`; исходный запрос № 3029
получил ровно один Desktop turn и одну квитанцию Telegram. Техническая
готовность к ручной приёмке восстановлена. Ручные D02–D17 остаются за
владельцем, Gate/MVP2 не приняты. [Квитанции выпуска](../gates/mvp2/m2-desktop/RELEASE-EVIDENCE-20261005-COMPAT.md).

## Наблюдение и причина

Сообщение Telegram № 3029 в теме «Codex work» создало запрос
`e2864d25-51a9-4b2b-897c-e99ec2090416` на продолжение точной задачи
`01a0848d-9432-74c1-800e-13a35882b26f` проекта `HomeEdit`.
Бот подтвердил приём, затем сообщил о недоступности Desktop. Рабочая БД
сохранила `waiting_pc`, позднее `failed`; `desktop_turn_id` остался пустым.
Один read-only IPC snapshot показал четыре прежних хода и **ноль** ходов с
`clientUserMessageId=nobus:e2864d25-51a9-4b2b-897c-e99ec2090416`.

Установленный Store-пакет `OpenAI.Codex_2p2nqsd0c76g0` обновился до
`26.930.4958.0`. Старый UIA-профиль принимал лишь `26.924.2738.0`.
Текущий Desktop IPC подключается, но выгруженная задача не имела owner до
открытия. После однократного семантического открытия UIA нашёл owner
**исходного thread ID**; прежняя проверка визуального заголовка уже не
соответствует новой разметке. В истории этой задачи один старый ход не
содержит поля `clientUserMessageId`; прежний парсер прекращал разбор с
`ValueError`. Рабочий каталог IPC совпал с выбранным проектом.

HTTP `/readyz` и Health 0 подтверждали работу Core, но не совместимость
UIA/истории конкретной задачи. Повторное открытие и повторная отправка
исходного промта не выполнялись.

## Устойчивое исправление

Кандидат `17651308ce8a9d6a1f27199955b13f42de019978` больше не
сравнивает номер сборки с константой. UIA на каждом действии проверяет
зарегистрированный пакет с точным family ID, статусами `Store` и `Ok` и
принадлежность процесса его каталогу установки. Номер версии только
отображается в квитанции. Семантические селекторы, пустой composer перед
созданием и прежние проверки IPC сохраняются. Для открытия существующей
задачи решающее подтверждение — owner **точного thread ID** из IPC, затем
проверка проекта и рабочего каталога до хода; изменившийся визуальный
заголовок не создаёт ложный отказ. Исторический ход без
`clientUserMessageId` допускается как `None`; явно некорректное поле всё ещё
отклоняется. При потерянном ACK отсутствие такого ID не разрешает
автоматическую повторную отправку.

Проверены 97 адресных тестов, синтаксис PowerShell 5.1 и живой read-only
UIA `Snapshot` без version argument на установленном Desktop. Изменённый
парсер прочитал четыре хода указанной задачи, подтвердил один исторический
пропуск ID, отсутствие нового хода и совпадение каталога. Это пока
`WIP/CHECKPOINT`, не выпуск и не ручная приёмка.

## Выпуск и безопасное восстановление

Кандидат прошёл L1 (`2975 passed, 3 skipped, 5` исторических deselected),
независимый L2 (`174 passed`) и адресную проверку границ. До смены кода
создана и проверена свежая копия четырёх БД. После штатного STOP, точного
backup-config и signed activation rebind первый Main завершился кодом 75:
Backup Task был ещё Disabled. Подписанный журнал оставался в `starting`,
recovery history — на прежнем rebind head, listener и дочерние процессы
отсутствовали. Backup включён; один исправленный запуск Main завершил **тот
же** backup cycle `PASS`, без повторного запуска цикла. Новая generation
`daily-20261005T165917-40954f964ca04e1d8415639ad7e9b22f` содержит
четыре VERIFIED БД; signed journal `complete`, Main/Health/Backup включены,
local/public readiness и плановый Health проходят.

После этого повторно прочитаны точный request и полная IPC-история.
Сохранённая запись оставалась `failed`, `desktop_turn_id=NULL`, полный
history содержал четыре прежних хода и ни одного с её `nobus:` client ID;
owner исходной задачи и её `cwd` совпали с проектом. Кодовый путь прежнего
отказа завершался на разборе истории **до** `start_turn`. Только эту запись
один раз перевели в `waiting_pc` через CAS. Watchdog создал ровно один ход
`01a10c69-55cb-7d02-869c-0a98e0cb4e19`; запись стала `delivered`,
единственная текстовая доставка `sent` получила Telegram message **3043**.
Старый завершённый D03 не запускался.

Ежедневная проверка стабильности может наблюдать доступность Desktop и
обнаруживать новую несовместимость, но не должна менять код из-за номера
версии. Если будущий выпуск действительно изменит UI-селекторы или приватный
IPC-контракт, безопасная остановка и адресное исправление сохраняются.
