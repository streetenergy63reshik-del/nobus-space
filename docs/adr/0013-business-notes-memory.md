# ADR 0013 — локальная память Telegram «Заметки бизнеса»

**Статус решения:** ACCEPTED
**Состояние реализации:** PARTIAL
**Дата:** 24 июля 2026

## Контекст

Владелец использует Telegram-форум «Заметки бизнеса» как оперативную
бизнес-память с отдельными темами. Оркестратор должен читать новые сообщения,
сохранять их после перезапуска и по точной команде формировать резюме либо
список задач. Содержимое заметок может быть конфиденциальным и не должно
автоматически передаваться внешней LLM.

## Решение

Для группового чата вводится отдельный тип server-side binding
`business_notes`. Binding версии 2 связывает точные `tenant_id`, owner
`user_id`, отрицательный Telegram `chat_id`, роль и назначение. Обычный
`owner_private` binding остаётся совместимым с версией 1.

Доверенная Telegram-граница валидирует и переносит `message_thread_id`.
Каждая заметка связывается с tenant, group, topic, `message_id`, `update_id` и
server timestamp. Повтор того же события идемпотентен; повторный `message_id`
либо `update_id` с другим payload отклоняется.

Текст заметок хранится в отдельной
`.runtime/business-notes.sqlite3`. Payload защищается Windows DPAPI; integrity digest вычисляется по
защищённому ciphertext, а не по открытому тексту. Незашифрованные tenant/chat/topic/message/update поля используются только для
точного выбора и проверки связи. При чтении проверяются digest, строгая схема
и совпадение всех границ.

Резюме и извлечение явных задач являются локальными детерминированными
операциями. Содержимое заметок не включается в Codex/OpenAI prompt. Ответ
возвращается в ту же тему и ограничивается безопасным размером Telegram.
Обычные сообщения индексируются без лишнего ответа.

Голосовая заметка транскрибируется локально и после успешной транскрипции
обрабатывается так же, как текстовая. Дополнительная кнопка подтверждения не
нужна: это owner-bound обратимое действие. Удаление заметок или производных
объектов остаётся отдельным action-bound L4.

Четвёртая runtime-БД включается в health, backup и restore. Backup manifest
имеет schema version 2; старый неполный manifest не принимается новой
версией restore.

## Последствия

Положительные:

- темы, tenants и групповые чаты изолированы;
- заметки переживают рестарт и входят в проверяемый backup/restore;
- конфиденциальный текст не отправляется внешней LLM;
- replay и конфликт Telegram identifiers закрываются на store boundary.

Остаточные ограничения:

- live group binding и owner smoke ещё не выполнены;
- индексируются только сообщения точно связанного owner, а не произвольных
  участников группы;
- автоматическое создание Google Tasks/Calendar из резюме в этот блок не
  входит и выполняется только отдельной точной командой владельца;
- retention/delete для заметок должен получить отдельный action-bound L4;
- локальное извлечение задач является rule-based, а не семантической моделью.
