Длина первоначального сообщения теперь передаётся вызывающим Telegram/Mini App кодом в доверенный контекст как `owner_message_break`. Значение вычисляется из сохранённого canonical input; оно не берётся из текста, ответа модели или пользовательского поля запроса. Структурные интервалы строятся отдельно для исходного сообщения и ответа. Открытый материал, незакрытая цитата или подставной текст «Уточнение владельца» в первом сообщении не могут захватить прямой ответ. Соседние прямые части соединяются для сохранения прежнего простого clarification пути. Источник операции проверяется по заново вычисленной таблице span с той же серверной границей; подмена границы не может использовать прежние span. Проверка условия и его command tail используют ту же границу.

Граница не передаётся модели и не добавляется в SQL, persistent JSON или CanonicalSemanticInput. При повторном CLARIFY связанное уточнение закрывается в обоих каналах. Mini App повторно не выдаёт token для цепочки, иначе очередной persisted canonical input потерял бы границу предыдущих сообщений. Повторное использование старого token не вызывает compiler и не создаёт задачу. Это зависимый путь общего изменённого парсера, а не новая функция Mini App.
