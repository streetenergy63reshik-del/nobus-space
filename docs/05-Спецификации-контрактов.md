# 05. Спецификации контрактов Nobus Space

**Статус документа:** CANONICAL

**CURRENT:** незакоммиченные Python-модели draft `schema_version="1"` реализованы частично

**TARGET:** выпущенные wire contracts `schema_version="1"` ниже обязательны до постоянного хранилища и Telegram E2E

## 1. Общие правила wire contracts

1. JSON UTF-8; неизвестные поля запрещены (`additionalProperties=false`).
2. Даты — RFC 3339 с timezone; authoritative времена задаёт сервер Core.
3. Идентификаторы task/attempt/event/request/bundle — UUID.
4. Строки trim; пустые значения и `bool` вместо integer запрещены.
5. Enum закрыты: неизвестное значение отклоняется.
6. Accepted contract/result/evidence/approval immutable; изменение создаёт новую revision.
7. `tenant_id` назначает trusted boundary. Любая ссылка проверяется на совпадение tenant/task.
8. SECRET не допускается в payload, prompt, result, evidence и logs.
9. Digest — `sha256:<64 lowercase hex>` канонического JSON или байтов артефакта.
10. Лимиты размера применяются до parse; точные transport limits конфигурируются и тестируются.

### Канонический JSON

Для revision object сериализуется с сортировкой ключей, без insignificant whitespace, UTF-8, с неизменёнными значениями строк и без самого поля revision. Массивы сохраняют порядок. Реализация обязана иметь golden compatibility tests; самостоятельные «почти одинаковые» алгоритмы digest запрещены.

### Идентификаторы

- `tenant_id`, `identity`, `quality_profile`, `policy_version`: 1–128 символов после trim;
- `idempotency_key`: 1–128 символов, unique вместе с tenant;
- human-readable instruction: 1–20 000 символов;
- acceptance criteria: 1–32 непустых уникальных строки;
- относительные/абсолютные пути сначала нормализуются, затем проверяются на containment; `..` и NUL запрещены.

## 2. CURRENT draft v1 и gaps до выпуска

Код `src/contracts/models.py` реализует:

| Contract | Поля CURRENT draft v1 | Известный gap до выпущенного v1 |
|---|---|---|
| `TaskContract` | task, tenant, idempotency, source, instruction, paths, permissions, risk, criteria, timeout, quality profile | нет `ingress_digest`, `contract_digest`, classification, policy version |
| `WorkerEvent` | task, sequence, event type, timestamp, payload | нет tenant/attempt/worker/contract binding и closed event enum |
| `VerificationBundle` | task, executor, L1/L2/L3 outcome, общий evidence list, verifier identities, status | нет tenant/contract/result binding и evidence на каждый level |
| `HumanApprovalRecord` | task, approver, timestamp, evidence ref | нет tenant/action/revision/request/expiry/decision binding |

CURRENT draft достаточен только для локальных policy tests и не является безопасным wire protocol. Поскольку ни внешний API, ни постоянные записи ещё не выпущены, модели изменяются на месте до полного v1 без параллельной схемы и адаптера миграции.

## 3. TrustedIngressEnvelope v1

Создаётся до LLM и не поступает от пользователя как готовый объект.

| Поле | Тип | Правило |
|---|---|---|
| `schema_version` | literal `"1"` | обязательно |
| `ingress_id` | UUID | server-generated |
| `tenant_id` | string | из server-side binding |
| `source` | enum | `telegram`, `api`, `scheduler` |
| `actor_identity` | string | аутентифицированная identity |
| `external_message_id` | string | update/message/job id |
| `idempotency_key` | string | stable key для повторной доставки |
| `received_at` | datetime | server time |
| `kind` | enum | `text`, `voice_preview`, `callback`, `system_job` |
| `content_ref` | string | sanitized content/artifact ref; не secret |
| `auth_context_ref` | string | ссылка на audit аутентификации |
| `envelope_revision` | digest | digest полей envelope |

Правила:

- unique `(tenant_id, source, idempotency_key)`;
- callback envelope дополнительно связывается с approval request/nonce;
- voice preview не создаёт исполняемую задачу до confirm;
- текст внутри content не может изменить поля envelope.

## 4. TaskContract v1

| Поле | Тип | Правило |
|---|---|---|
| `schema_version` | literal `"1"` | обязательно |
| `task_id` | UUID | один logical task |
| `tenant_id` | string | совпадает с envelope |
| `idempotency_key` | string | unique внутри tenant |
| `ingress_digest` | digest | binding к trusted envelope |
| `source` | enum | `telegram`, `api`, `scheduler` |
| `instruction` | string | нормализованное поручение, не system policy |
| `allowed_paths` | array[string] | может быть пустым; containment обязателен |
| `permissions` | array[enum] | закрытый capability set; пусто = read-only |
| `risk` | enum | `low`, `medium`, `high`, `critical` |
| `data_classification` | enum | `public`, `internal`, `confidential`; `secret` запрещён в contract |
| `acceptance_criteria` | array[string] | 1–32 проверяемых критерия |
| `result_profile` | string | версия ожидаемого формата результата |
| `timeout_seconds` | integer | 1–3600, не bool |
| `quality_profile` | string | профиль обязательных проверок |
| `policy_version` | string | политика на момент принятия |
| `created_at` | datetime | server time |
| `contract_digest` | digest | canonical digest всех остальных полей |

Минимальный permission registry MVP:

- `repo.read`;
- `repo.write_allowlisted`;
- `process.run_allowlisted`;
- `artifact.write_allowlisted`;
- `external.read_allowlisted`;
- `external.write_l4`.

Новый permission требует ADR/policy change и тестов. LLM не может добавлять permissions. Даже наличие `external.write_l4` означает «можно запросить approval», а не «можно писать без approval».

## 5. WorkerEvent v1

WorkerEvent — факт от worker, не команда для state transition.

### Общие поля

| Поле | Тип | Правило |
|---|---|---|
| `schema_version` | literal `"1"` | обязательно |
| `event_id` | UUID | unique |
| `tenant_id` | string | binding к Task |
| `task_id` | UUID | binding к Task |
| `attempt_id` | UUID | binding к попытке |
| `contract_digest` | digest | ровно исполняемый контракт |
| `worker_identity` | string | authenticated worker identity |
| `sequence` | integer ≥ 1 | строго возрастает в attempt; не bool |
| `event_type` | enum | см. ниже |
| `emitted_at` | datetime | время worker, не authoritative |
| `payload` | object | strict schema по event type |

Storage добавляет `observed_at` server time и raw event digest. Unique constraints: `event_id` и `(tenant_id, task_id, attempt_id, sequence)`.

### Event types

| Type | Payload | Допустимый смысл |
|---|---|---|
| `started` | `{lease_ref}` | worker начал attempt |
| `progress` | `{stage, percent?}` | наблюдаемая телеметрия, не status permission |
| `waiting_input` | `{question_ref}` | требуется вход; Core решает переход |
| `artifact_ready` | `{artifact_refs[]}` | промежуточные артефакты |
| `result_ready` | `{result_ref, result_revision, result_digest}` | immutable result сохранён |
| `usage` | `{provider, model?, input_units?, output_units?, amount?, currency?}` | только измеренный usage/cost |
| `failed` | `{error_code, safe_message, retryable}` | sanitized failure |
| `cancelled` | `{reason_code}` | attempt остановлен |

Payload не принимает credentials/token/cookie/password/secret/authorization на любой глубине. `result_ready` с чужим tenant/task/contract отклоняется. Неизвестный event type — protocol error, а не `ignored` success.

| Поле | Тип | Правило |
|---|---|---|
| `result_id` | UUID | unique |
| `tenant_id` | string | совпадает с Task |
| `task_id` | UUID | совпадает с Task |

## 7. EvidenceRef и VerificationBundle v1

### EvidenceRef

| Поле | Тип | Правило |
|---|---|---|
| `kind` | enum | `test_report`, `diff`, `manifest`, `log_excerpt`, `artifact`, `reproduction`, `review`, `auth`, `external_receipt` |
| `uri` | string | internal immutable location/reference |
| `digest` | digest | проверка содержимого |
| `media_type` | string | MIME/type profile |
| `classification` | enum | не выше `confidential`; secret запрещён |

### VerificationLevelRecord

| Поле | Тип | Правило |
|---|---|---|
| `level` | enum | `l1`, `l2`, `l3` |
| `verifier_identity` | string | distinct identity |
| `method` | string | воспроизводимое описание/профиль |
| `outcome` | enum | `passed`, `failed` |
| `checked_at` | datetime | server-observed time |
| `evidence` | array[EvidenceRef] | минимум один ref для `passed` |
| `notes` | string? | безопасные ограничения/причина failure |

### VerificationBundle

| Поле | Тип | Правило |
|---|---|---|
| `schema_version` | literal `"1"` | обязательно |
| `bundle_id` | UUID | unique |
| `tenant_id` | string | Task binding |
| `task_id` | UUID | Task binding |
| `contract_digest` | digest | contract binding |
| `result_revision` | integer ≥ 1 | последовательная result binding |
| `result_digest` | digest | integrity binding результата |
| `executor_identity` | string | frozen с ResultRecord |
| `levels` | array[VerificationLevelRecord] | prefix `l1`, затем `l2`, затем `l3` |
| `status` | enum | `draft`, `approved`, `rejected` |
| `quality_profile` | string | совпадает с contract |
| `policy_version` | string | policy проверки |
| `provenance_ref` | EvidenceRef | manifest версий model/prompt/tools/source для этой result revision |
| `usage_refs` | array[EvidenceRef] | связанные usage/cost записи; пусто только при доказанном отсутствии расхода |
| `created_at` | datetime | server time |
| `locked_at` | datetime? | обязателен для approved/rejected |
| `bundle_revision` | digest | digest bundle |

Условия `approved`:

- есть ровно L1, L2, L3 с `passed`;
- executor, L1, L2, L3 попарно различны после нормализации identity;
- каждый уровень имеет собственное evidence;
- task/tenant/contract/result/quality profile совпадают;
- после L3 bundle audit-locked;
- completion повторно валидирует сохранённый bundle, не принимает replacement из update.

## 8. Approval contracts v1

### ApprovalRequest

| Поле | Тип | Правило |
|---|---|---|
| `request_id` | UUID | unique |
| `tenant_id`, `task_id` | string, UUID | task binding |
| `contract_digest`, `result_digest` | digest | integrity binding контракта и результата |
| `result_revision` | integer ≥ 1 | последовательная result binding |
| `action_type` | enum | closed adapter-specific registry |
| `action_preview` | object | безопасное точное описание эффекта |
| `action_digest` | digest | canonical action binding |
| `risk` | enum | high/critical либо external write |
| `requested_by` | identity | Core/service identity, не L4 |
| `requested_at`, `expires_at` | datetime | server time; expires > requested |
| `callback_nonce_digest` | digest | raw nonce не хранится в сообщении/логах |
| `policy_version` | string | policy на момент запроса |

### ApprovalDecision

| Поле | Тип | Правило |
|---|---|---|
| `decision_id`, `request_id` | UUID | unique и binding |
| `tenant_id`, `task_id` | string, UUID | совпадают с request |
| `approver_identity` | string | authenticated, не executor/L1/L2/L3 |
| `decision` | enum | `approved`, `rejected` |
| `decided_at` | datetime | только server-observed time |
| `auth_evidence_ref` | EvidenceRef | evidence аутентификации/callback |

Решение действительно только если request не использован, не истёк, actor уполномочен, nonce совпал, revisions/action digest не изменились. Сохранение decision и переход `waiting_human → human_approved|rejected` атомарны.

`HumanApprovalRecord` — immutable projection approved decision. Approval не переносится на новый result/contract/action, другой tenant/task и не разрешает «похожие» действия.

## 9. Состояния и переходы

| Current | Допустимые next |
|---|---|
| `pending` | `parsing` |
| `parsing` | `routing`, `draft`, `failed` |
| `routing` | `in_progress`, `failed` |
| `in_progress` | `draft`, `waiting_input`, `failed` |
| `waiting_input` | `in_progress`, `failed` |
| `draft` | `l1_validated`, `rejected`, `rework`, `deferred`, `escalate` |
| `l1_validated` | `l2_verified`, `rejected`, `rework`, `escalate` |
| `l2_verified` | `l3_approved`, `rejected`, `rework`, `escalate` |
| `l3_approved` | `completed`, `waiting_human`, `rejected`, `escalate` |
| `waiting_human` | `human_approved`, `rejected`, `escalate` |
| `human_approved` | `completed`, `executing`, `rejected` |
| `executing` | `completed`, `failed`, `escalate` |
| `rejected` | `rework` |
| `rework` | `in_progress`, `draft` |
| `deferred` | `in_progress` |
| `escalate`, `completed`, `failed` | нет |

Дополнительные guards:

- переходы L1/L2/L3 требуют соответствующего сохранённого prefix bundle;
- после DRAFT executor frozen;
- foreign bundle запрещён на любом сохранении;
- high/critical: `l3_approved → waiting_human → human_approved → completed`;
- для внешнего действия: `l3_approved → waiting_human → human_approved → executing → completed|failed|escalate`;
- `human_approved → completed` допустим только для внутреннего результата без внешнего эффекта;
- любое внешнее действие следует тому же L4 пути, даже при low/medium;
- server-side expiry job атомарно выполняет `waiting_human → rejected` с `reason_code=approval_expired` без создания `ApprovalDecision`;
- invalid update не изменяет Task и `updated_at`;
- terminal records immutable.

## 10. Concurrency, replay и retry

- Task row имеет monotonically increasing `version`; update — compare-and-swap.
- Event sequence проверяется транзакционно.
- Approval request имеет single-use state.
- Worker claim использует lease; истёкший lease не даёт старому worker записать result.
- Retry создаёт новый attempt; task id и `contract_digest` сохраняются.
- External write повторяется автоматически только если adapter предоставляет проверенную idempotency semantics. Иначе неизвестный outcome → `escalate`.

## 11. Ошибки

Boundary возвращает stable error code и безопасное сообщение. Raw audio, temp path, prompt, credentials, provider response и exception chain наружу не передаются.

Минимальные коды: `validation_failed`, `unauthenticated`, `forbidden`, `duplicate`, `conflict`, `policy_violation`, `approval_expired`, `worker_timeout`, `provider_failed`, `external_outcome_unknown`, `internal_error`.

## 12. Pre-release evolution и совместимость

1. Текущие draft-модели не были опубликованы, закоммичены как Gate 1 или сохранены в постоянной базе, поэтому они заменяются на месте полным v1.
2. `schema_version="1"` замораживается только после golden digest/round-trip tests и первого Telegram E2E.
3. Reader принимает только перечисленные выпущенные версии; угадывание tenant/revision запрещено.
4. Database constraints повторяют tenant/idempotency/sequence uniqueness.
5. После выпуска любое несовместимое изменение требует новой версии, inventory, migration, rollback plan и ADR.

## 13. Acceptance tests контракта

Обязательны позитивные и негативные тесты:

- unknown field, wrong enum, bool-as-int, naive datetime;
- secret key на любой глубине;
- cross-tenant/task/revision mismatch;
- duplicate idempotency/event/callback;
- event sequence race;
- result replacement after L1/L2/L3;
- verifier identity collision;
- evidence missing per level;
- expired/replayed/foreign approval;
- result/contract change after approval;
- invalid mutation leaves state and timestamp unchanged;
- old worker writes after lease expiry;
- external timeout produces escalation, not blind retry.
