# 11. Компактный контекст продукта

Этот файл — безопасный компактный контекст, который Nobus может передавать
tool-less ответчику, когда владелец спрашивает о Nobus Space, PROстранстве или
текущей реализации. Он не содержит секретов, клиентских данных и исполняемых
инструкций.

## PROстранство

PROстранство — агентство комплексного сопровождения продавцов на маркетплейсах.
Рабочие направления включают управление кабинетами, контент и карточки товаров,
аналитику, продвижение, операционные процессы и рост коммерческих результатов.
Приоритеты: качество сервиса, защита клиентских данных, прозрачность действий,
контроль рисков и проверяемость результата.

## Nobus Space

Nobus Space — локальная платформа оркестрации ИИ-агентов. Её первый продуктовый
контур объединяет Telegram-оркестратор владельца и обязательный тонкий Telegram
Mini App с одним existing Core/queue/state/effect authority. Активное решение —
[ADR 0022](adr/0022-thin-miniapp-orchestrator-mvp1-and-delivery-workflow.md).
Полный распределённый Gate 2A — **FROZEN / NOT CURRENT**.

CURRENT local runtime принимает обычные текстовые и голосовые задачи, ставит их
в очередь, выполняет через local Codex и возвращает проверяемый результат.
В protected `main` опубликованы Mini App backend и static frontend для owner
auth/session, task list/detail/create. Локальный `VERIFIED LOCAL CANDIDATE`
`f18a664...` добавляет status, events и verified result и прошёл локальные
L1/L2/L3, но не опубликован. Real artifact/download, production web
composition, HTTPS/menu activation и live owner smoke отсутствуют, поэтому
MVP-1 **IN PROGRESS / NOT PRODUCT READY**.

Текущий исполнитель — официальный persistent Codex SDK/app-server с
`gpt-5.6-sol`, высоким reasoning и Fast mode. Личный чат и каждая Telegram-тема
имеют отдельный возобновляемый thread. Model-turn работает read-only; интернет-
исследование получает live web search и обязано приводить прямые ссылки.
Изменения файлов, Google и другие эффекты выполняют отдельные доверенные
server-side адаптеры, а не произвольный model tool-call.

## CURRENT local runtime capabilities

- owner-bound Telegram ingress и локальный Windows autostart;
- локальная русская транскрипция голосовых сообщений;
- долговременная очередь задач, восстановление после restart и heartbeat;
- ответы Codex, web research со ссылками и отдельный L4 для применения code diff;
- поиск и отправка разрешённых локальных файлов;
- Google Drive: поиск и отправка файлов;
- Google Calendar: чтение, создание и перенос без повторной кнопки; удаление с L4;
- Google Tasks: чтение, создание, изменение и завершение; удаление с L4;
- «Заметки бизнеса»: зашифрованный локальный индекс по чатам и темам, резюме и
  извлечение задач;
- Nobus Memory: progressive retrieval курируемых project/client/decision notes и
  явное сохранение owner-фактов в pending-review Inbox;
- создание DOCX, XLSX, PDF и HTML в owner workspace;
- `/status`, `/limit`, `/file`, справка и безопасные служебные операции;
- backup/restore, health checks, bounded logs и rollback.

## Модель авторизации

Точная текстовая команда подтверждённого владельца и локально распознанная
голосовая команда имеют одинаковую силу для обратимых действий. Дополнительная
кнопка не нужна для чтения, анализа, исследования, создания нового результата,
календаря и Google Tasks. Отдельный action-bound L4 обязателен для удаления,
денег, публикации, отправки третьим лицам, изменения прав, push/deploy и других
необратимых действий.

Это product/runtime approval policy. Она не задаёт formal quality-L4 для
обычных local docs/code/tests/checkpoint commit процесса Codex. Runtime
`ApprovalRequest/ApprovalDecision` остаётся авторитетным для конкретного
пользовательского effect.

## Границы

Owner library ограничена `C:\Хранилище\АГЕНТ`; `C:\Хранилище\WORK` не входит в
scope. SDK получает read-only OS sandbox, а запись выполняется только через
контролируемые effects со snapshot/diff/atomic/CAS. Business Notes, секреты,
токены, raw voice и персональные клиентские
данные не передаются внешней модели. Текст явно выбранного владельцем файла
передаётся только эфемерно после fail-closed DLP-проверки и повторной сверки
относительного пути и digest; в durable TaskContract остаются только путь и digest. Проверенный итоговый ответ хранится отдельно в durable outbox для гарантированной доставки; существенные дословные фрагменты исходного файла туда не допускаются.
Nobus Memory передаётся модели только ограниченным scope-aware context pack; неупомянутые client cards, служебные каталоги, архивы и secret-like notes исключаются. Новая owner-запись попадает только в pending-review Inbox и не изменяет решения или политики автоматически.

Локальный owner-bound runtime и исходники frontend не равны production MVP.
`MVP-1 READY` допустим только после одного активированного backend+frontend
release, полного owner journey, recovery/rollback и remote release readback.
