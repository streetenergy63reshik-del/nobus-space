# ADR-0002. Детерминированное ядро и сменные LLM-воркеры

**Статус решения:** ACCEPTED

**Дата:** 2026-07-20

## Контекст

LLM недетерминированы, меняются у провайдеров, зависят от лимитов и могут следовать недоверенному контенту. Связывать права, состояние и завершение задачи с конкретной моделью небезопасно и дорого для замены.

## Решение

Nobus Core реализуется обычным кодом и остаётся владельцем:

- contracts и schema validation;
- tenant isolation, idempotency и event ordering;
- risk/permission policy;
- state transitions;
- L1/L2/L3/L4 guards;
- audit и cost records.

LLM, CLI и API adapters — сменные workers с минимальными capabilities. Их output всегда недоверен до schema/policy/quality checks. Для MVP используется модульный монолит; отдельные сервисы и broker вводятся только по измеренной необходимости.

## Последствия

Положительные:

- провайдера или модель можно заменить без смены state machine;
- тестируется policy независимо от LLM;
- отказ или prompt injection не дают дополнительных прав.

Отрицательные:

- требуется явный wire protocol и adapter на каждого worker;
- часть удобной «агентской магии» заменяется строгими отказами;
- независимые verifiers увеличивают время выполнения.

## Отклонённые варианты

- LLM как главный оркестратор — не обеспечивает воспроизводимость и security boundary.
- Микросервисы с первого дня — повышают сложность без нагрузки, оправдывающей её.

## Проверка решения

Core tests выполняются без сети и LLM; замена worker не меняет contract/state semantics; неизвестные events, permissions и transitions блокируются.
