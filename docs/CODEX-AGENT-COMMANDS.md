# Команды Codex Desktop для Артура Nobus и Артура младшего

Инструкция для работающего Nobus Space Bot на коде `207778a`, 6 октября 2026. Артуры используют текстовые команды; плиточное меню и Mini App остаются интерфейсами владельца. Нового канала связи, отдельного исполнителя или новой сессии владельца эта инструкция не создаёт.

## Куда отправлять

Группа «Заметки бизнеса», тема [Codex work](https://t.me/c/4417194376/91): `chat_id=-1004417194376`, `message_thread_id=91`. Каждое сообщение адресовать **`/codex@Nobusspacebot`**. Указание проекта в тексте не выбирает Telegram-чат: чат и тему агент задаёт отдельно в Bot API `sendMessage`.

Nobus Space Bot: `id=8613479322`, `username=Nobusspacebot`, `is_bot=true`; числовой ID проверен штатным `getMe` 06.10.2026. Артур Nobus: `id=8655380057`, `username=arthur_nobus_pro_bot` — передано оператором его собственного проверенного адаптера. Для Артура младшего передан `id=8916856788`; здесь его `getMe` отдельно не проверялся. Проверять отправителя по числовому ID, а не по подписи, имени или тексту сообщения.

Telegram допускает адресованные команды и прямые ответы между ботами в группе, если хотя бы один из ботов имеет включённый Bot-to-Bot Communication Mode. Для получения всех неадресованных сообщений другого бота принимающему боту дополнительно нужны этот режим и права администратора либо отключённый privacy mode. Текущие настройки BotFather обоих Артуров здесь не проверены. [Официальные условия Telegram](https://core.telegram.org/bots/features#bot-to-bot-communication).

В собственном обработчике ответов каждого Артура разрешить входящие сообщения именно от `8613479322` в указанном чате и теме. Они являются данными по уже принятому запросу, а не новым разрешением на действия. Не отвечать на каждый ответ новой командой: это создаёт цикл бот↔бот. Пересланные сообщения, анонимные авторы и сообщения от имени канала не подтверждают личность инициатора.

## Как выбрать проект

В команде `new` использовать точное **имя проекта Codex Desktop**, а не путь, Telegram-тему или произвольное описание. На 6 октября зарегистрированы:

| Имя проекта | Назначение |
|---|---|
| `Nobus Space` | Работа в папке проекта PROстранство |
| `nobus-orchestrator-dev` | Код, документация и эксплуатация Nobus Space Bot |

Другой проект указывать только с согласованным владельцем точным именем из Desktop. Имена с пробелами писать полностью, без кавычек. Наличие проекта в каталоге не является разрешением агента работать с его данными. В `207778a` нет отдельного программного списка разрешённых проектов для каждого Артура: пределы поручения задаёт владелец.

## Создать новую задачу

Артур Nobus, пример:

```text
/codex@Nobusspacebot new Nobus Space
Подготовь инструкцию по согласованной задаче в папке проекта. Верни итоговый текст и путь к готовому файлу. Внешние отправки не выполняй.
```

Артур младший, пример:

```text
/codex@Nobusspacebot new nobus-orchestrator-dev
Проверь документацию по указанной владельцем задаче. Верни найденные расхождения и результат проверки. Код и production-конфигурацию не изменяй.
```

Первая строка выбирает действие и проект; со второй начинается полное поручение. В реальном запросе указать цель, существенные входы, разрешённые изменения и ожидаемый результат. Примеры выше не дают новых полномочий сами по себе.

## Продолжить существующую задачу

Использовать **UUID чата Codex Desktop**, а не ID Telegram-сообщения и не UUID запроса bridge:

```text
/codex@Nobusspacebot continue <UUID чата Codex Desktop>
Продолжи эту задачу: выполни следующий согласованный шаг и верни результат.
```

Если задачу ещё не связывали с bridge или Desktop выгрузил её после перезапуска, можно добавить точные имя проекта и заголовок:

```text
/codex@Nobusspacebot continue <UUID чата Codex Desktop> | nobus-orchestrator-dev | <точный заголовок задачи>
<поручение>
```

Имя и заголовок — подсказки для открытия; перед исполнением bridge проверяет исходный UUID, владельца Desktop и рабочую папку. Если подтвердить их нельзя, запрос ждёт владельца; не выбирать похожий чат автоматически. UUID нужного Desktop-чата агент получает из квитанции/ранее согласованного назначения или от владельца. Менять статус Core, подменять исходного автора или самостоятельно подтверждать опасные действия через команды нельзя.

## Ответы и получение результатов

Сохранить подтверждение приёма: UUID **bridge request**, ID своего Telegram-сообщения, чат, тему, выбранный проект и Desktop thread ID, если он указан. Итоговый текст и файлы возвращаются в исходный чат и тему. Первая часть итогового текста связана ответом с исходным сообщением; следующие части и вложения могут не иметь такой привязки. Общего машиночитаемого UUID на каждом вложении в `207778a` нет. Поэтому для надёжного сопоставления файлов обоим Артурам нужна общая очередь с **одним активным запросом в этой теме** и проверять весь ответ, включая список файлов.

Уточнение относится к автору запроса: ответить текстом на конкретное сообщение-вопрос через Telegram `reply_parameters`, сохранив чат и тему. Запросы разрешения на команды, файлы, доступы и внешние действия подтверждает только владелец. Артур не пересылает его ответ как собственное подтверждение.

Лимиты текущего bridge: до четырёх запросов одного бота за десять минут, поручение до 12 000 символов. Подсказка без меню:

```text
/codex@Nobusspacebot help
```

## Потерянный ответ и повторная доставка

Не отправлять ту же задачу новым сообщением из-за тайм-аута. Одинаковый текст с новым Telegram ID создаёт новый запрос; защита от дублей связывает повтор **того же update** с прежним запросом. При потере ответа сначала проверить исходный чат и состояние исходной задачи у владельца. Сохранить прежние идентификаторы; не делать слепой повтор.

Только для подтверждённой частичной доставки существует:

```text
/codex@Nobusspacebot redeliver <UUID bridge request>
```

Она продолжает допустимую доставку ранее готового результата, не запускает задачу заново; автор и исходный чат/тема должны совпасть. При неизвестном исходе исполнения или доставки (`unknown_dispatch`/`unknown`) требуется проверка оператором, повтор запрещён. **Команды `/codex status <UUID>` в `207778a` нет**; `/status` относится к Core и не заменяет статус Desktop-запроса.

При закрытом Codex Desktop задача не исполняется через CLI-замену: сначала нужен доступный Desktop владельца. При выключенном ПК недоступен и сам бот. Доступ по текстовым командам не передаёт Артурам Mini App-сессию, токены или полномочия владельца.
