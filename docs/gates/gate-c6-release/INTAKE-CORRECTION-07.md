# Исправление приёма C6 — контракт рабочего пакета

9 сентября 2026. Статус: WIP, live не изменён.

Цель: владелец завершает зависшую отправку Mini App и создаёт следующую задачу без повторного исполнения, потери принятой задачи или ложного сообщения о готовности.

Исполнитель кода один. Зона: src/storage/sqlite_store.py, src/application/miniapp.py, durable_product.py, semantic_admission.py (только если нужна типизация диагностики), product_status.py, src/transport/miniapp.py и miniapp_static/app.js; относящиеся tests, forward ADR и документация C6. Существующие четыре изменения документов C6 сохраняются. BASE и LIVE не редактируются этим пакетом.

Подтверждённые блокеры: pending без срока/конечного пути, невозможность отмены pending, отсутствие причины отказа, ложная общая готовность, время сессии вместо времени поступления, исторический счётчик без пояснения. Первоначальное исключение реального запроса неизвестно.

Решение: существующий защищённый журнал хранит время/срок/стадию/типизированный код. Общая SQLite-транзакция сериализует закрытие заявки и ingress claim; принятая задача имеет приоритет, закрытая заявка запрещает новый claim в том числе при восстановлении durable queue. Неизвестный исход сверяется, модель не повторяется. Legacy-заявка разрешается тем же способом при чтении на новой версии. Схема SQL по возможности сохраняется; существующие envelopes и bindings не переписываются.

Критерии остаются C6-01…C6-08 из ACCEPTANCE-FREEZE-01, digest sha256:c266ff98f9d5959c1ebb272b6b593d71f613704f653941a58593808db325e2e5. Сохранность, один Core/semantic/worker/ASR, RTO ≤1800 с, резервирование RPO 24 ч и 7 daily/4 weekly, безопасный restart, реальные пользовательские сценарии и ≥900 с, явная приёмка и постоянная фаза, та же памятка и v1.0.2.

Риск высокий: гонки отмены/приёма, восстановление очереди, auth/tenant/replay, потерянный ответ, сохранность legacy. Во время WIP выполняются относящиеся offline проверки. Затем один цельный замороженный кандидат и один разрешённый независимый L2/L3; прежние проверки неизменных bytes не повторяются. Только после PASS — разрешённая публикация C6 ветки и обычный PR/merge. Новый live target и совокупная бюджетная дельта предъявляются владельцу до переключения; итоговая приёмка остаётся отдельной обязательной точкой.
