# C6 — результат эксплуатационной проверки

Бот работает для пользовательской приёмки на опубликованной версии `7ceab0eca570b7810add2fbe600285a7fa3eee91`. Постоянный режим и v1.0.2 ещё не приняты. Данные и прежние задачи сохранены.

Кандидат `sha256:9bedab26845d319ddb7d8ea7c00af1f65f8d62f57a6fc669d902d71c7567df35` и восемь критериев приёмки остаются замороженными. Единственный заключительный L2/L3 завершён ранее; код и проверки не повторялись. [Фиксация](ACCEPTANCE-FREEZE-01.md), [последующие улучшения](FOLLOW-UP.md).

Один production запуск был остановлен из-за ошибки моего вспомогательного скрипта чтения процессов: Windows PowerShell5 неверно прочёл кириллический путь UTF8. Вызов переведён на уже установленный PowerShell7, данные после остановки сверены. Следующий запуск успешен; исходный код продукта не менялся. Ошибка и её расход бюджета сохранены.

Основное задание и проверка состояния включены. Backup после проверочного цикла отключён до итоговой приёмки; это ещё не постоянное ежедневное резервирование. После приёмки остаются принятая постоянная конфигурация, обязательная следующая копия, финальное обновление памятки и публикация v1.0.2.

Верхние оценки времени ASR достигли исходных 1200 секунд. Запрошено разрешение ещё на 240 секунд для двух оставшихся операций; предел 12 распознаваний и остальные лимиты сохраняются. Новых операций ASR до ответа нет. Это ограничение исходного бюджета, не новый критерий приёмки.

Полные безопасные агрегаты и привязки локальных доказательств: [OPERATIONAL-STATUS-06.json](OPERATIONAL-STATUS-06.json). Документ — эксплуатационный checkpoint; приёмку владельца он не заменяет.
