# ADR-0003. «Канал продаж» как минимальная доменная абстракция

**Статус решения:** ACCEPTED

**Дата:** 2026-07-20

## Контекст

Первый бизнес-контур относится к маркетплейсам, но в будущем возможны собственные сайты. Привязка Core к Ozon/Wildberries усложнит новый adapter; универсальная commerce-платформа сейчас была бы спекулятивной.

## Решение

В доменных ссылках использовать минимальную пару `sales_channel` + `external_object_ref`. Конкретные операции, схемы данных и permissions остаются в adapter каждого канала.

В MVP реализуются только реально нужные каналы. «Собственный сайт» остаётся TARGET и не порождает интерфейсы/таблицы до первого подтверждённого сценария.

## Последствия

Положительные:

- Core не знает деталей маркетплейса;
- доменная ссылка остаётся пригодной для нового adapter.

Отрицательные:

- adapter должен переводить внешние ID и ошибки;
- нельзя обещать переносимость операций, которых нет в общем контракте.

## Guardrail YAGNI

Не вводить каталог универсальных сущностей, workflow designer или общий язык запросов. Добавлять поле/операцию только по фактическому use case и compatibility test.

## Проверка решения

Второй реальный channel adapter должен подключаться без изменения Core state/policy, кроме явного permission/action registry.
